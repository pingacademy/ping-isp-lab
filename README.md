# Ping ISP: Course Lab

The free lab for **[IP/MPLS: Zero to Service Provider](https://ping-academy.pages.dev/ip-mpls)**, a video course by [Ping Academy](https://ping-academy.pages.dev) on [YouTube](https://www.youtube.com/@pingacademy).

One network, used from the first lab to the capstone. 13 routers running [FRRouting](https://frrouting.org) in [Containerlab](https://containerlab.dev). Free, open source, and runs on a laptop.

```
   CE1 ─── PE1 ─────── P1 ═══════ P2 ─────── PE3 ─── CE3
            │  ╲       │          │       ╱  │
            │    ╲     │          │     ╱    │
   CE2 ─── PE2 ─────── P3 ═══════ P4 ─────── PE4 ─── CE4
                         ╲      ╱
                            RR
```

| Role | Routers | Job |
|---|---|---|
| **P** (provider core) | P1, P2, P3, P4 | Fast transit. Never talks to customers. |
| **PE** (provider edge) | PE1, PE2, PE3, PE4 | Where customers plug in. All the "smart" services live here. |
| **RR** (route reflector) | RR | Distributes BGP routes so PEs don't need a full mesh. |
| **CE** (customer edge) | CE1, CE3 = **Blue Corp** · CE2, CE4 = **Red Bank** | The customer's own router. |

Provider AS: **65000** ("Ping Telecom"). Full addressing in [ADDRESSING.md](ADDRESSING.md).

**Addressing at a glance**
- Loopbacks: `10.255.0.X/32`, where X is the router number (P1 = .1, PE1 = .11, RR = .100)
- Core links: `10.1.<link>.0/31`, one /31 per link

## Requirements

- A **Linux** machine or VM with **Ubuntu 22.04/24.04**, 4 vCPU and 8 GB RAM.
  MPLS forwarding needs the Linux kernel's MPLS modules. Ubuntu's stock kernel has them.
  On Mac or Windows, run an Ubuntu VM (UTM, VirtualBox, VMware, Multipass) or a small cloud VM.
- Docker + Containerlab (installed below).

## Install (one time)

```bash
# Docker + Containerlab in one step (official quick setup)
curl -sL https://containerlab.dev/setup | sudo -E bash -s "all"

# Enable MPLS in the kernel (needed from Section 4 onwards)
sudo modprobe mpls_router
sudo modprobe mpls_iptunnel
printf "mpls_router\nmpls_iptunnel\n" | sudo tee /etc/modules-load.d/mpls.conf
```

Log out and back in so your user can run Docker.

## Get the lab

Inside your Ubuntu machine or VM, clone it into a folder called `Lab` (that's the name the episodes use):

```bash
sudo apt install -y git      # if git isn't installed yet
git clone https://github.com/pingacademy/ping-isp-lab.git Lab
cd Lab
```

No git? Use **Code → Download ZIP** on GitHub, unzip it, rename the folder to `Lab`, then run `chmod +x stage.sh`.

To get new stages as the course grows: `cd Lab && git pull`.

## Run the lab

```bash
cd Lab
sudo containerlab deploy -t ping-isp.clab.yml      # start (loads stage 00-base)
docker exec -it clab-ping-isp-PE1 vtysh             # open a router's CLI
sudo containerlab destroy -t ping-isp.clab.yml     # stop
```

## Stages: jump to any episode

Each episode starts from a known state. Load it with:

```bash
./stage.sh                  # list stages
./stage.sh 06-addressing    # load a stage and redeploy
```

| Stage | State | Use it for |
|---|---|---|
| `00-base` | Hostnames + interface descriptions, no IPs | Start of E06 |
| `06-addressing` | Loopbacks + all core links addressed | End of E06 / start of Section 2 |
| `11-isis` | IS-IS level-2 core, wide metrics, passive loopbacks, overload bit on the RR | End of Section 2 / start of Section 3 |
| `16-bgp` | iBGP from each PE to the RR over loopbacks (next-hop-self); RR reflects; P routers stay BGP-free; each PE originates one test prefix (see ADDRESSING.md) | End of Section 3 / start of Section 4 |

More stages are added as the course is built (`26-ldp`, `34-l3vpn`, …).

To check every stage end to end on your own Linux machine (deploys each one and tests IS-IS, the RR overload bit and BGP): `bash .github/test-lab.sh`.

## For maintainers

All configs are generated by `build_lab.py`. **Edit the script, not the .conf files**, then run:

```bash
python3 build_lab.py
```

This repository is published from the course's source repository, so changes made here directly will be overwritten. Report problems as issues instead.
